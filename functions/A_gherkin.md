# A_gherkin — every s0/s1/s2 scenario as a formal predicate

Team A catalog. Analyzed source: hologram-ai (MIT OR Apache-2.0), HEAD `c9609c0`, read-only. Feature files are in `features/suites/{s0_addressing,s1_acquisition,s2_compilation}/`.

Step bindings:
- **Rust executor:** `crates/hologram-ai-conformance/tests/bdd.rs` (cucumber-rs). Features are selected from `model/dictionary.toml` rows with `executor = rust` and the feature's `@lane:` tag (`bdd.rs:5024–5046`). Runs use `fail_on_skipped`.
- **Browser executor:** `apps/web/bdd/steps.mjs` (cucumber-js, `strict: true`, tags `@executor:browser and not @live`, `apps/web/bdd/cucumber.mjs`).

**Nothing in this file comes from running their suites.** Every result is from reading step bodies. GitHub Actions on `SNAPKITTYAGENT9NOVA/hologram-ai` lists **0 workflow runs** (checked 2026-10-07 PT), so no CI result exists to cite either.

## Form and columns

Each scenario is written as `name : Given-state → When-input → Then-postcondition`. The table columns are:
- **Step real**:
  - `Y` means every Then step is bound and can fail when its literal text is violated.
  - `N` means at least one Then is tautological, text-only for an ordering claim, or vacuous for the requests the product actually makes.
  - `Unbound` means a step has no definition. Under `strict: true` that is a failure.
- **Subject**: whether the steps exercise product code (`product`) or a test-local stand-in (`stand-in`).
- **Authority**: what the dictionary row names, and whether the steps consult it at test time:
  - `consulted` means external data or an external engine is used.
  - `named` means it is listed only.
  - `self` means the reference is generated by this repo.
- **Verdict**:
  - **Implemented** means Step real = Y and Subject = product.
  - **Asserted-only** covers every other case.

The arithmetic domain is bytes and ℕ throughout. The two float-tolerance scenarios are noted where they occur.

The repo's claim (README:7) is: "every feature begins as a Gherkin definition, and every claim is validated against an authority this repository did not author."

The first half (feature → Gherkin) holds for the dictionary rows. `crates/hologram-ai-model/src/honesty.rs` enforces a feature per row. Slice code that has no row or scenario at all:
- the native downloader (`crates/hologram-ai/src/download/`)
- `hologram-archivum`
- the ONNX DynamicQuantizeLinear and MatMulInteger decompositions
- `quantize_weights`
- the `DirKappaStore` path handling

The second half holds for 14 of 40 scenario instances. The other 26 break down as:
- 3 (G-06…08) name `blake3-kats` but use no KAT.
- 2 (G-38, G-39) name GGML without consulting it.
- 7 (G-18…22, G-25, G-26) name `hf-hub` but run against the hermetic server or a fixed list.
- 14 (G-12…17, G-23, G-24, G-27, G-28, G-34…37) rely only on `journey-reference`, which this repo generates with its own pipeline.

The honesty gate (`honesty.rs:43`) does not check that a build row's scenarios consult an external authority.
